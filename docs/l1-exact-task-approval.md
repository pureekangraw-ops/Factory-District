# Exact-task L1 capability — implementation and release handoff

Owner approved this bounded capability on 2026-10-22. Parent coordinates merge, deployment and live execution. This candidate has only been tested locally; a local receipt is not production evidence.

The only additional allowed PANTHEON tuple is LOGIC / CREATE_L1_TEXT_ARTIFACT / EXECUTE:TEXT_ARTIFACT:L1 for task_d6c9e93a42fd4f339bb47d941428dd08 and request hash de0038fe8be999fe6a1c725156cd9684ac4887127ef783a659148ccdf36d0b24. Checkpoint and pass remain cp-<task_id> and work-pass://pantheon-<task_id>. LOGIC is the ownership domain; no trainee runner or CODE/VISUAL/provider is called. This task identity is reserved against all legacy intents on both rail principals.

The pure formatter produces fixed UTF-8 text: YGG FACTORY L1 PASS, task/checkpoint identity, original request hash, and an ISO timestamp. The timestamp, exact artifact bytes, SHA-256 digest, deterministic receipt ID and source SHA are stored together in one immutable compare-and-set record. Storage uses the existing private RECORD_STORE binding, at records/factory/l1/<task_id>/<request_hash>. No bucket, credentials, IAM, public URL, Drive integration, deletion or external execution is introduced.

A single R2 conditional create is both the execution claim and the artifact/receipt commit. There is no separately committed claim that can strand a timestamp, and no intermediate receipt without artifact bytes. Concurrent calls return the winning record. A lost response is resolved by rereading that same record; repeated calls do not write another artifact. Readback verifies the stored artifact against the exact request and persisted timestamp and recomputes its digest. Corrupt/missing evidence never produces verified success. Reconciliation is read-only.

Authenticated /station/preflight, /station/receive, /station/reconcile and /station/readback/<receipt_id> use the existing isolated PANTHEON HMAC rail. The deterministic L1 receipt is restricted to that principal; unsigned/City reads are denied. The result embeds the tiny artifact bytes, reference, digest, timestamp and correlations so the caller can verify the actual bytes.

PANTHEON's paired candidate uses a static exact-task grant (no schema migration), preserves original action/task/request/hash, reserves this task from its generic local run/recover/retry path, claims Factory dispatch in a D1 transaction, and marks completion only after authenticated fresh Factory readback and digest verification. An explicit approved dispatch may resume an uncertain job only after definitive RECEIPT_NOT_FOUND; immutable Factory CAS prevents a late original request from producing a second effect. Reconcile alone does not execute. Completed replay validates stored task/action/run/receipt correlations and fresh Factory evidence. Owner GET also reads Factory freshly and fails if evidence is unavailable.

Tests cover exact allowlist, forbidden legacy substitution, concurrent immutable writes, timestamp persistence across restart, lost response, absent effect, corrupt bytes, and the existing Factory suites. The paired cross-repository test exercises real GO, OwnerBridge, WorkHub and Factory modules with local D1/R2 substitutes; it is not a deployed-storage test.

Release order: Factory candidate, then PANTHEON candidate, then existing GO caller patch. Parent must verify deployed source identities before allowing the existing task through GO queue, explicit dispatch and owner readback. Acceptance requires original task/hash unchanged; exactly one artifact/receipt; recomputed digest of returned bytes; verified source/checkpoint/pass; and replay without another effect. Report queue, execute, receipt, artifact and owner verification separately. Rollback disables ingress while retaining evidence; never delete artifacts or reset completed work.
